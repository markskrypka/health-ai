# research — bounded probes

Every probe starts by writing three lines: the question, the decision it
informs, and the timebox. Research without a decision to inform is
waste — say so and skip it.

## Depth — decide it yourself, say it in one line

Two depths, chosen the same way work gets sized — never wait to be
asked for "deep research":

- **Scan** — the default: one probe agent, one question, a short
  timebox.
- **Deep** — several probe agents in parallel (still in the foreground),
  each briefed with a different angle — alternatives, primary sources,
  counter-evidence, current state — findings cross-checked before the
  recommendation.

Escalate to Deep unprompted when any of these hold: the decision is
High-stakes or hard to reverse; the question spans alternatives or
trade-offs ("which", "compare", "best way"); the facts move fast
(versions, pricing, APIs, ecosystems); or a Scan came back thin,
conflicting, or surprising. Never hand back thin findings when the
triggers say Deep — widen once, say so, and still stop at the timebox.

## Delegation

Delegate discovery to the probe agent (foreground, read-only, web
allowed) or the host's built-in explorer. The brief always demands:
findings with sources or file paths, uncertainty marked, a
recommendation, and a summary-only return.

Persist the finding as a short note before acting on it:

- initiative work → `docs/planning/active/<slug>/research/<date>-<topic>.md`
- standalone → `docs/planning/research/<date>-<topic>.md`

Note shape: the question · findings, each marked verified / strong /
inferred · the recommendation · gaps. Never claim more certainty than
the evidence carries; "not found" is a valid finding and gets written
down too.

Stop at the timebox: recommend with what exists, or ask the user for
more time. Never silently keep digging.
