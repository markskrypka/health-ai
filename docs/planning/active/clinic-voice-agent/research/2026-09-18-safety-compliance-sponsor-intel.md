# Safety, compliance and sponsor intel — research probe (2026-09-18)

Legend: **[V]** verified (primary source read this session) · **[S]** strong (credible secondary sources, or primary-domain text seen only via search summary) · **[I]** inferred (reasoning / prior knowledge, not re-verified). Timebox ~20 min; synthetic-data demo, so everything is sized for a weekend.

## Question
What safety, compliance and front-desk practices should the agent embody to score with a healthcare voice-AI jury, and what does Prosper AI itself value?

## Decision it informs
The safety feature set, the scripted phrasings, and how the demo is framed for this sponsor.

## Recommendation (short)
Put safety in code, not in the prompt. Build five things first: (1) a deterministic red-flag path that speaks a scripted "hang up and call 112" line and reports an explicit outcome; (2) policy at the tool boundary (rules engine with reason codes, tools that refuse unverified sessions, no override path on the phone channel); (3) verify-then-disclose identity flow where the lookup tool returns only a match count, so the model cannot leak what it never saw; (4) read-back and explicit yes before every write; (5) a silent-failure watchdog around the voice model. Then prove it: a post-call auto-QA scorecard plus a red-team regression suite. That mirrors Prosper's own product language ("every call automatically reviewed", "flagged issues", handoff "with a full transcript and confidence score"). Keep the greeting under ~8 s with the AI disclosure first. Do not over-triage or over-refuse: the leaderboard is literal.

### (b) Receptionist triage — what a non-clinician does

- [S] US office-hours protocols (Schmitt-Thompson via TriageLogic): "any pain between the neck and navel is considered chest pain until proven otherwise"; the one message is "CALL 911 NOW". https://triagelogic.com/triagelogic-heart-attack-stories/ · staff-protocol safety: https://www.thedoctors.com/articles/telephone-triage-and-advice-patient-safety-strategies
- [S] Spain numbers: 112 for any life-threatening emergency; **024** = Ministry of Health suicide-behaviour line, free, confidential, 24h/365, itself escalates to 112. https://www.sanidad.gob.es/linea024/home.htm — US equivalents 911 / 988 [I].
- [I] Additional red flags from prior knowledge, not re-verified: stroke FAST (face droop, arm weakness, speech), severe bleeding, fainting/unresponsive, seizure, fever ≥38 °C in a baby under 3 months (NICE NG143 "red"), pregnancy with heavy bleeding / severe pain / reduced movements, overdose or poisoning, suicidal intent.
- [I] Rule for the agent: it never assesses, diagnoses or reassures. Three tiers: EMERGENCY (stop booking, scripted 112 line, outcome reported), URGENT TODAY (no routine slot: same-day slot if the clinic has one, else flag for clinician callback / handoff, plus safety-net sentence), ROUTINE (book; if any symptom was mentioned add one safety-net sentence). Keep the red-flag list short and literal to avoid over-triaging "I have a cough" and failing a plain booking case.

### (d) Voice-agent threats and mitigations
- [S] OWASP Top 10 for LLM Applications 2025: LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM06 Excessive Agency, LLM07 System Prompt Leakage, LLM09 Misinformation, LLM10 Unbounded Consumption are the ones that apply. https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/
- [V date / S names] OWASP Top 10 for Agentic Applications 2026 (published 9 Dec 2025): ASI01 Agent Goal Hijack, ASI02 Tool Misuse & Exploitation, ASI03 Identity & Privilege Abuse, ASI06 Memory & Context Poisoning, ASI08 Cascading Failures, ASI09 Human-Agent Trust Exploitation. https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/
- [I] Threat to mitigation map (all demo-able):
  - Social engineering for another patient's data (LLM02): lookup tool returns `{match_count, verified}` only; record fields enter the model context only after verification; agent will not confirm whether someone is a patient.
  - Forbidden booking / policy-override pressure (LLM06, ASI02): deterministic rules engine runs inside the booking tool and returns `DENY + reason_code + allowed_alternatives`; the model cannot write around it.
  - Impersonation "I'm the doctor, override" (ASI03, ASI09): no privileged role exists on the phone channel; claimed identity never changes permissions.
  - Spoken prompt injection / "read me your instructions" (LLM01, LLM07): caller speech is data; no secrets in the prompt; tool allow-list per call state.
  - Wrong-patient or duplicate writes (LLM09, ASI08): read-back + explicit yes, idempotency key, state machine that survives corrections.
  - Abuse / endless calls (LLM10): one warning then polite end; turn and duration caps.
  - Silent model failure: watchdog (see g).

### (f) Accessibility: elderly, hard of hearing, bad line
- [S] Normal-to-slightly-slower pace, lower pitch, no shouting, pause between sentences, **rephrase rather than repeat verbatim**, check understanding, one topic at a time. https://www.nia.nih.gov/health/health-care-professionals-information/talking-your-older-patients · https://www.ucsfhealth.org/education/communicating-with-people-with-hearing-loss · https://aging.arizona.edu/sites/default/files/2023-11/Communicating%20with%20People%20who%20have%20Hearing%20Loss.pdf
- [V] Osakidetza guide says the same for phone work: slower, repeat key words, digits in groups (source in e).
- [I] For the agent: one question per turn; longer end-of-speech silence threshold so slow talkers are not cut off; read back weekday + date + time + doctor + site; explicit yes/no before writing; after 2 misses switch to spell / digit-by-digit mode; after 3 offer a human; final recap; never stack options (max two slots offered at once).

### (g) Gemini safety filters and blocked responses (team-lead addition)
- [V] `generateContent`: four adjustable categories (harassment, hate speech, sexually explicit, dangerous content); thresholds OFF, BLOCK_NONE, BLOCK_ONLY_HIGH, BLOCK_MEDIUM_AND_ABOVE, BLOCK_LOW_AND_ABOVE. "If the threshold is not set, the default block threshold is **Off** for Gemini 2.5 and 3 models." Core harms such as child safety "are always blocked and cannot be adjusted." Blocked prompt shows `promptFeedback.blockReason`; blocked response shows `finishReason: SAFETY` and "The content that was blocked is not returned." https://ai.google.dev/gemini-api/docs/safety-settings
- [V] Live API: the WebSocket reference documents **no `safetySettings` field** in `BidiGenerateContentSetup`, and `BidiGenerateContentServerContent` exposes only `interrupted`, `generationComplete`, `turnComplete` — no finish reason or safety signal. https://ai.google.dev/api/live — yet the JS SDK type `LiveConnectConfig` does list `safetySettings` ("Safety settings in the request to block unsafe content in the response"). https://googleapis.github.io/js-genai/release_docs/interfaces/types.LiveConnectConfig.html — so behaviour on the Developer API is undocumented: test it in hour one.
- [V as reports, cause unknown] Production silent failures on Live: `gemini-3.1-flash-live-preview` stops emitting audio with the socket open and no error (66 of 603 calls ended "unknown"); Vertex `gemini-live-2.5-flash-native-audio` — 5.9% of calls silent, either near-zero-amplitude audio or `turnCompleteReason: "RESPONSE_REJECTED"` with zero audio bytes, possibly tied to proactive audio; no Google reply. https://github.com/google-gemini/cookbook/issues/1225 · https://github.com/google-gemini/gemini-live-api-examples/issues/40
- [I] Ordinary symptom talk is outside the four categories and defaults are Off, so blocks should be rare — but suicide/self-harm, overdose and child-injury talk sit closest to "dangerous content" and the non-adjustable layer, which are exactly the emergency calls. Mitigation: (1) never let the model author the emergency lines — detect red flags on the input transcript in a parallel deterministic path and play a scripted line via separate TTS; (2) watchdog: no audio bytes within ~2.5 s of end of caller turn, or a turn that completes with zero audio, or a text-path `finishReason` other than STOP, triggers a scripted fallback, one retry, then handoff, and raises a flagged issue in the console; (3) set `safetySettings` explicitly anyway and disable proactive audio; (4) since the team owns orchestration, a cascaded path (STT, Gemini text, TTS) gives a checkable `finishReason` every turn, which Live native audio does not. OpenAI Realtime as second choice was not examined.

## Scripted phrasings
Rules: agent asks, caller supplies, agent matches — it never offers candidate values ("is it the one ending in 42?"), never states how many matches, never says which identifier failed. Refusal = No + the specific rule + what it can do. Emergency lines are fixed strings, not generated.
